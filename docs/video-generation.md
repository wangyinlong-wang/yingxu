# MiniMax H3 与 Hypit 视频制作

本功能把视频素材生成与成片制作接入原有生产流程。默认仍使用 FFmpeg；H3 只在内容页明确选择「生成本镜头 AI 视频」后调用，普通 `all / assets / render`、保存设置和 GET 查询不会创建付费视频任务。

## 配置 MiniMax H3

在「模板与设置 → 模型与视频」的视频模型卡片填写：

- 来源：第三方模型；协议：MiniMax H3 V2。
- Base URL：`https://metaso.cn/api/minimax`，模型名：`MiniMax-H3`。
- 密钥：通过「保存密钥」写入本机 macOS 钥匙串，与数据目录、能力、来源和地址绑定。设置响应仅包含存在状态；API Key 不进入 SQLite、普通设置、日志或 Git。
- 非 macOS 可设置 `PUBLISHER_VIDEO_API_KEY` 环境变量。钥匙串中已有值时优先使用该地址保存的密钥；钥匙串锁定或拒绝访问时不会静默切换账户。
- 启用模型，并保存设置。此过程不调用生成接口。

视频设置提供每段 4–15 秒（默认 6 秒）和 `768P / 2K`（默认 768P）。界面参考价为 Metaso 公布的 768P 每秒 ¥0.09、2K 每秒 ¥0.15（核对日期：2026-09-20），提交前会显示预计费用；它不代表余额查询或实际账单，最终以服务商结算为准。

默认仍为文生视频。API 的单次视频请求可显式选择 `reference_image_asset_id` 和可选 `reference_audio_asset_id`，以本人授权的图片/声音作参考。仅该请求将选定素材以 data URI 发往已配置的 H3 服务商；普通生成、设置读取和未选择参考的视频请求不会上传肖像或声音。素材 ID 与 SHA-256 固定到任务中，发送前再次核验；图片支持 JPEG/PNG/WebP，声音参考需 2–15 秒，图片和声音原文件均不超过 10 MB。已上传的 M4A/AAC/FLAC/OGG 会在本机从核验过的原始字节转换为 WAV 后发送，原文件不变；MP3/WAV 直接使用。音频参考须同时提供图片。API 不接收任意远程素材 URL，不把 data URI 写入任务、日志或响应。暂不支持首尾帧、参考视频或再生成参数。

[Metaso 官方客户端与接口说明](https://github.com/meta-sota/ComfyUI-MiniMaxH3-API)

## 使用视频素材

1. 在内容的「镜头与素材」中选择图片类型的分镜，填写画面提示词。
2. 点击「生成本镜头 AI 视频」，核对时长、分辨率与参考费用后确认。数据卡、引语卡、文字卡继续使用本地准确文字渲染。
3. 任务结束后，在 AI 视频素材字段预览并选择生成片段。清除选择可恢复原图片画面。
4. 准备好图片（用于封面）和旁白后，点击合成视频。默认使用已选择的配音；数字人口播可在「音频素材」中单独选择「使用所选 AI 视频原声」，沿用视频音轨保持口型同步。原声不能与其他配音混选，无音轨的视频会被拒绝。标题、字幕和背景音乐仍由本地合成。片段过短时停留末帧，过长时截取需要的时长；不会自动追加付费生成。
5. 新成片继续执行质检和人工审核。生成片段不会直接发布，也不会沿用旧视频的审核结果。

修改分镜画面提示词、旁白或分镜类型时，旧片段关联会清空，已生成文件保留在素材库。显式选择其他片段时，以用户选择为准。

## 安装和使用 Hypit

需要 Node.js ≥22.15、npm、FFmpeg/ffprobe，以及 Chrome/Chromium。先完成 README 中的后端环境安装，再在项目根目录执行：

```bash
bash scripts/setup_hypit.sh
```

脚本安装固定版本 Hypit `0.2.10`，以及该版本声明的 HyperFrames `0.7.101`。工具放在 `.tools/hypit/`，运行环境放在当前 `data_dir/hypit/`；这些目录均被 Git 忽略。已有运行配置保留，不改变全局 npm 或其他模型设置。

脚本优先使用系统 Chrome/Chromium。需要指定浏览器时，首次安装前设置 `PUBLISHER_HYPIT_CHROME_PATH` 为可执行文件路径；没有系统浏览器则由 Hypit 准备其声明的固定浏览器版本。运行配置中的 `chromePath`、并发和缓存均属于本机配置。服务器/容器需自行提供可启动的浏览器环境。

在设置中把「画面渲染方式」切换为 Hypit，再合成视频：

- 应用生成受控 SVML/SVRUN 工程，复用已有图片和视频片段，不在 Hypit 中调用第三方生成模型。
- 图片的推进、拉远、平移由 Hypit 渲染；视频以原速播放并在不足时保持末帧。
- 现有 FFmpeg 流程继续负责旁白、音量、字幕、Logo、数字人叠加、封面和最终 MP4。
- 字幕仍以实测音频时长和短句权重分配时间，不是 WhisperX 词级对齐；本次没有启动 WhisperX，也不占用其默认端口。
- 缺依赖、版本不符或渲染失败会明确报错，不会暗中换回 FFmpeg。可在设置中主动选择 FFmpeg 后创建新的合成任务。

## 恢复、取消与费用边界

MiniMax 使用 `POST /v2/video_generation` 创建任务，随后 `GET /v2/query/video_generation/{task_id}` 查询。系统在提交前记录调用意图；已知任务 ID 会持久化。查询或下载失败时，重试只处理同一个任务；轮询不计为新的模型调用。创建请求超时、HTTP 408、5xx 或缺失有效任务 ID 时，必须核验服务商记录，系统不会自动再发 POST。

取消本地任务会停止轮询；Metaso 当前文档没有撤销生成端点，因此不能保证服务商取消或停止计费。任务 ID 会保留，便于继续查询。服务商已明确终止的任务不会自动创建替代任务。下载仅允许受现有公网地址校验保护的 URL，最多 50 MB，密钥不会发给下载地址；下载未完成保留任务 ID。

Hypit 的 `build` 同样不是幂等命令。每个本地渲染工程把 Build ID 保存到 `data_dir/runs/<job_id>/render/hypit/build.json`。恢复查询同一 Build，取消时显式执行 `hypit cancel`；提交结果未明时暂停重复提交。构建日志保留在本地 Hypit 项目中，可使用安装的 CLI 查看：

```bash
.tools/hypit/node_modules/.bin/hypit status <build-id> --workspace <工程目录> --runtime <data_dir>/hypit/runtime.json
.tools/hypit/node_modules/.bin/hypit logs <build-id> --workspace <工程目录> --runtime <data_dir>/hypit/runtime.json
```

## 接口与兼容

- `models.video`：新增可选能力，第三方 `minimax_h3` 协议，默认未启用。
- `video.renderer`：`ffmpeg | hypit`，默认 `ffmpeg`。
- `video.clip_duration`：4–15，默认 6；`video.clip_resolution`：`768P | 2K`。
- `POST /api/v1/settings/model-keys/video`：复用独立凭据接口。
- `POST /api/v1/contents/{id}/generate`：`{"stage":"video","scene_id":"...","clip_duration":6,"clip_resolution":"768P"}` 仅生成指定分镜的片段。页面提交确认弹窗中的时长和分辨率，任务固定使用这些参数；后续配置修改不会改变已确认的费用参数。旧客户端同时省略这两个参数时使用提交时的设置默认值。
- 分镜新增可空 `video_asset_id`，关联当前内容的 `video_clip` 素材；跨内容片段关联被拒绝。
- `audio_asset_ids` 支持仅填写该分镜的 `video_asset_id` 来选用原声；更换或清除视频会清除旧原声关联，普通音频选择保持兼容。
- `POST /api/v1/local-ai/transcribe` 可接收 `video_clip` 素材 ID，在本地核对视频口播；不会自动更改旁白或声明核验通过。
- 任务增加 `can_resume_video` 元数据，任务中心可继续查询原视频。

这些是现有 JSON 字段的增量扩展，不新增数据库表或列。旧设置读取时补默认值；旧客户端省略分镜视频字段时保留原关联。取消使用时选择 FFmpeg、清空分镜视频选择并关闭视频模型；文件和任务记录保留。直接降级到不认识新 JSON 字段的旧版代码前，应备份数据库并处理对应设置/分镜字段，不能用删文件代替数据回退。

Hypit 是独立可选运行时，其许可不被本项目 MIT 覆盖，详见 [第三方声明](../THIRD_PARTY_NOTICES.md)。
