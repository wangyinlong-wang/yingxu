# V1 implementation contract

The approved product is a local, single-operator Vue 3 + FastAPI application. No cloud hosting or paid calls during development without explicit authorization. Following explicit user authorization, an opt-in mode automatically submits approved content to bound platform accounts; every final click requires a durable submission fence. All timestamps are UTC ISO 8601 strings; IDs are UUID strings. Client labels are Chinese. Sources, model output and device UI are untrusted data. No HTML interpretation of user/model/source text.

## API

Base `/api/v1`. Success bodies are resources, list bodies `{items: [...], total: number}`. Errors `{code, message, request_id, details?}`. Async responses HTTP 202 `{job_id, status}`. JSON field names use snake_case. PATCH content MUST include `version`; mismatch returns 409. POST job/publication operations accept `Idempotency-Key`, generated once per user action and reused on transport retry. No automatic retry of mutations by frontend.

Resources below list all fields needed by UI; extra server fields can be ignored.

- `GET /health`: `{status, version}`. `GET /dashboard`: `{counts:{topics,contents,review_required,published,failed_jobs},recent_jobs:Job[],recent_contents:Content[],usage:{calls_today,tokens_today,cost:null},environment:Diagnostics}`.
- `GET /sources`, `POST /sources` `{name,kind:'rss'|'hackernews'|'x'|'x_tikhub',url,enabled:true}`; `PATCH /sources/{id}` updates name/url/enabled and permits only `x` ↔ `x_tikhub` kind changes; `POST /sources/{id}/collect` submits collection. TikHub requires `{expected_kind:'x_tikhub'}`; legacy free sources accept an omitted body. Source `{id,name,kind,url,enabled,last_collected_at,last_error,created_at}`.
- `GET /topics?q=&limit=100`: Topic `{id,source_id,title,url,summary,published_at,score,relevance_score,selection_reason,status,created_at}`. `POST /topics/{id}/content` `{template_id?:str}` returns Content; repeated creation returns existing active content. `POST /topics/{id}/dismiss` marks ignored.
- `GET /contents?q=&status=`; `GET /contents/{id}` returns Content `{id,topic_id,title,version,status,template_id,script:{angle,selection_reason,facts:[{claim,source_url,verified,notes}],platforms:{douyin:{title,description,tags:string[]},xiaohongshu:{title,description,tags:string[]}}},scenes:[{id,order,narration,caption,image_prompt,image_asset_id:null|str,audio_asset_ids:string[]}],video_asset_id,cover_asset_id,subtitle_asset_id,created_at,updated_at}`. Status `DRAFT|GENERATING|REVIEW_REQUIRED|APPROVED|REJECTED`.
- `PATCH /contents/{id}` `{version,title?,script?,scenes?,template_id?}` returns updated Content and invalidates review/derived media when inputs change. Platform copy uses weighted title counting (full-width/non-ASCII 2, ASCII 1): Douyin max 60 units, Xiaohongshu max 40; each rendered description plus hashtags is max 1000 Unicode characters. `POST /contents/{id}/generate` `{stage:'all'|'script'|'assets'|'render'|'local_voice'|'motion'}` submits Job. `POST /contents/{id}/approve` `{version,notes?,auto_publish_expected?,compliance_confirmed:true}` requires rendered current video, resolved facts, complete valid platform copy, an AI-assistance disclosure in both descriptions and explicit human compliance confirmation. `POST /contents/{id}/reject` `{version,notes}`. `GET /contents/{id}/export` downloads ZIP of current video, cover, SRT and platform text.
- `POST /assets` multipart `file`, `kind:image|audio|bgm|logo|voice_reference|portrait`, optional `content_id` -> Asset `{id,kind,filename,mime_type,size,url,created_at}`. `GET /assets?content_id=`; `GET /assets/{id}/file` raw bytes with Range support. Asset URL always this endpoint. For content UI setting image_asset_id/audio_asset_ids via versioned PATCH is the replacement operation.
- `GET /jobs?status=&limit=100`, `GET /jobs/{id}` Job `{id,kind,content_id,status,progress,current_step,error_code,error_message,created_at,updated_at,steps:[{name,status,detail,started_at,completed_at}],result}`. `POST /jobs/{id}/cancel`, `POST /jobs/{id}/retry` (blocked for uncertain model outcome or active publication; frontend displays backend explanation). Status `QUEUED|RUNNING|WAITING_USER|SUCCEEDED|FAILED|CANCELED`.
- `GET /accounts`, `POST /accounts` `{platform:'douyin'|'xiaohongshu',display_name,account_identifier,device_serial}`; PATCH same fields; one per platform. Account includes id and created_at.
- `GET /devices` `{items:[{serial,state,model?}],total}`; `POST /devices/{serial}/inspect` `{platform}` returns `{serial,platform,app_version?,account_identifier?,ready,warnings:string[]}`. Diagnostics returns `adb:{available,version?,supported}` and warns below Android Debug Bridge 1.0.41. Inspect is explicitly user-triggered; diagnostics never installs Android software.
- `GET /publications` Publication `{id,content_id,content_version,content_title,platform,account_id,status,job_id,work_url,work_id,evidence,created_at,updated_at}`. `POST /publications` `{content_id,content_version,account_id}` submits preparation and returns `{job_id,status,publication_id}`. Only approved current content. Status `PREPARING|WAITING_USER|VERIFYING|PUBLISHED|NEEDS_ATTENTION|CANCELED`. `POST /publications/{id}/confirm-media-selection` `{confirmed:true,notes}` is restricted to the XHS 9.46 `MEDIA_SELECTION_REQUIRED` recovery: it verifies stopped job, current approval/snapshot/account/device, unexpired continuity evidence, exact remote SHA-256 and current final editor, then writes an auditable operator confirmation without submit timestamps; identical repeats are idempotent. `POST /publications/{id}/confirm` `{work_url,work_id?,confirmed:true,notes?}` explicitly records user-confirmed real publication. `POST /publications/{id}/detect` has no body and reads the currently open work from the frozen bound phone: it requires a completed prior account verification, an idle publication job, the frozen platform-specific approved title and a unique platform share link before atomically recording `PUBLISHED`; repeat after success is idempotent. Official `xhslink.cn/.com` short links are expanded through the guarded public-network path and tracking queries are removed. `POST /publications/{id}/cancel` `{notes?}` releases reservation; no automatic phone cleanup. `POST /publications/{id}/resume` reruns guarded preparation on same reservation. `POST /publications/{id}/collect-metrics` submits device read job. Cannot create duplicate active or published same content/platform/account even across revisions; cancellation cannot erase a confirmed publication.
- `GET /metrics?publication_id=` list Metric `{id,publication_id,platform,content_title,views:null|int,likes:null|int,comments:null|int,favorites:null|int,shares:null|int,source:'device'|'manual',raw,observed_at}`. `POST /metrics` `{publication_id,views?,likes?,comments?,favorites?,shares?,observed_at?,notes?}` requires published work and is always source manual. `GET /analytics` `{publications:[],metrics:[],reports:[]}`; `POST /reports` submits model report generation, result saved as `{id,date,body,created_at}`. Empty/no evidence reports should not fabricate recommendations.
- `GET /templates`; `POST /templates` `{name,description,prompt,style:'brief'|'explain'}`; `PATCH /templates/{id}` same; Template adds id,version,updated_at.
- `GET /settings` `{models:{text:ModelConfig,image:ModelConfig,speech:ModelConfig},video:{width:1080,height:1920,fps:30,target_seconds:60,font_path:'',bgm_asset_id:null,logo_asset_id:null},limits:{daily_calls:40,daily_videos:1},timezone:string}`. ModelConfig `{base_url:'',model:'',timeout_seconds:number,voice:'alloy',size:'1024x1536',json_mode:false,key_configured:boolean,enabled:false}`. Fixed env names `PUBLISHER_TEXT_API_KEY`, `PUBLISHER_IMAGE_API_KEY`, `PUBLISHER_SPEECH_API_KEY`; NEVER accept keys over API. `PATCH /settings` partial nested same shape except key_configured (read only). `GET /diagnostics`: `{python,ffmpeg:{available,version?},ffprobe:{available},adb:{available},models:{text:{configured},image:{configured},speech:{configured}},storage:{free_bytes},workers:{content:{online,last_seen},device:{online,last_seen}},warnings:string[]}`.
- `GET /schedules`; `POST /schedules` `{name,kind:'pipeline'|'metrics',time:'09:00',timezone,enabled:false,daily_limit:1}`; PATCH same; adds id,last_run_at,next_run_at. Enabling requires configured enabled models for pipeline and daily limits. No paid connection tests by just loading or saving settings. Worker only executes enabled schedules; timezone from server IANA local timezone, no catch-up burst.

## Integration modules (assigned to backend integration agent)

No DB imports, no FastAPI routes. Synchronous pure/application functions, injectable callbacks for side effects managed by main worker. Own only `backend/app/integrations/{__init__,sources,media,device,errors,net}.py` and `backend/tests/test_integrations*.py`.

`errors.py`: `IntegrationError(code: str, message: str, *, uncertain: bool=False)` safe errors, and `CanceledError` subclass. No secrets/body dumps.

`net.py`: `safe_get(url: str, *, max_bytes:int=5_000_000, timeout:float=20) -> tuple[bytes,str,str]` returns body/content-type/final-url. Public HTTP(S) only, resolve and reject all loopback/private/linklocal/reserved addresses, validate each redirect, disallow credentials, limit response bytes, default TLS validation. Test SSRF, redirects and large responses. Model endpoints are main-owned and user-configured separately.

`sources.py`: `collect_source(source:dict, *, limit:int=30) -> dict`, source kind rss/hackernews and url. Return `{items,complete,scanned,candidates,warning}`; each item contains title,url,summary,published_at (ISO string or null),score,relevance_score(0..100),selection_reason. Use `safe_get` with TLS verification, public IP pinning and bounded RSS/HN reads. Partial collections disclose their actual range; an empty result remains empty. Script generation may separately call `fetch_article_excerpt` for the selected public source when its summary is insufficient; that excerpt is saved in the job input snapshot. No recursive article crawling.

`media.py`: `probe_media(path:Path)->dict` ffprobe parsed duration/width/height etc. `compose_video(*,title:str,scenes:list[dict],output_dir:Path,settings:dict,progress:Callable[[str,int],None],canceled:Callable[[],bool])->dict` where scene has `image_path:str`, `audio_segments:[{path:str,text:str}]`, `caption:str`. settings video width,height,fps,font_path plus optional bgm_path,logo_path,style. Return `{video_path:str,cover_path:str,subtitle_path:str,duration:float}`. Use actual speech segment durations for SRT, normalized image cover and Chinese overlay with Pillow, Ken Burns/fade transitions, H264 yuv420p/AAC, 1080x1920 default. subprocess argv only; safe font discovery; check disk and input existence. Do not invent voice. Support cancellation during FFmpeg and progress callback heartbeats. BGM optional volume reduction, logo optional. Meaningful tests with real short local audio/video fixtures, ffprobe, Unicode and missing-file cases; small resolution tests are fine, delivery output stays default.

`device.py`: `list_devices()->list[dict]` read-only CLI, no daemon start if adb absent; `inspect_device(serial:str,platform:str)->dict`; `prepare_upload(*,serial:str,platform:str,account_identifier:str,video_path:str,cover_path:str,caption:str,progress:Callable[[str,int],None],canceled:Callable[[],bool],previous_evidence:dict|None=None,title:str|None=None,description:str|None=None)->dict`; `collect_metrics(*,serial:str,platform:str,account_identifier:str,work_url:str,work_id:str,content_title:str)->dict`. prepare returns `{status:'WAITING_USER',evidence:dict}` when at final editor; may return `{status:'NEEDS_ATTENTION',evidence:{reason,...}}` for unsupported/ambiguous UI. Metrics returns nullable views/likes/comments/favorites/shares plus raw evidence. Validate serial safe input, platform allowlist, package names, account exact match; do not click login/permission/captcha/final publish or install APK silently. UIAutomator2 must require already-initialized server on device; missing setup raises DEVICE_SETUP_REQUIRED. Read actual hierarchy, use resource/text selectors and guarded page transitions; no blind coordinate selection. Unknown selector/page/video match stops, not fake success. Support editor resume guarded by expected caption/media evidence. Missing device actual acceptance is unverified, not supported-on-all-versions. Unit tests may use fake device transport, but label as unit only.

## Main ownership

Main agent owns all remaining backend files: app config, SQLAlchemy models, migrations, API, model calling/cost limits, persistent worker/scheduler, content pipeline and tests; docs and scripts. Frontend agent owns frontend only. No agent edits outside its assignment, creates grandchildren, commits, pushes, deploys or makes paid calls. Everyone is sharing the checkout; preserve others' changes. Flag contract gaps before changing signatures.

## Durable execution rules

Atomic queue claim and versioned edits; short SQLite transactions, no HTTP or FFmpeg while DB write lock held. Worker heartbeats/leases and restart recovery; generated outputs keyed by input hash and cached before advancing. Models are user-configured OpenAI-compatible endpoints with no implicit retries; request begun without definitive response becomes WAITING_USER/model outcome unknown, never automatically billed again. Published/unknown publication must not be retried as a new post. Device reservation spans WAITING_USER and survives worker restart. Facts with missing source or unverified status prevent approval. Tests use fixture inputs explicitly; real billing, UI upload and publication need respective user configuration/authorization.

### Verified device contract additions

On the calibrated Douyin 40.4.0 flow, title and description are separate fields. When supplied, both must match the approved combined caption; each field is read back after entry. The preparation function stops before the final 发布 / 发作品 action. The separately authorized automatic submission step verifies fresh evidence and records intent before clicking once. Current visible control bounds determine integer tap positions, with unique-target, foreground-package and screen-boundary checks. Each video and its cover share a dedicated fingerprint-named album; both are scanned, the video hash and one-row media inventory are checked, and only a single matching video grid item may be selected. Unknown pages remain an explicit handoff; no claim of universal device/version compatibility.

On XHS 9.46, an operator-selected video may resume only after the explicit audited media confirmation above. Sleeping devices reuse the existing one-attempt Keychain PIN flow and latch before editor verification. Caption controls are re-read from a fresh hierarchy after `set_text`; stale selectors are not treated as content proof. Authorized automatic submission recognizes only the observed `发笔记` control, then requires the `声明内容来源` sheet, uniquely selects `含 AI 合成内容`, and clicks `确认并发布`; any mismatch stops after the durable intent fence.

## Quality and automation amendment (2026-09-10)

Optional fields: `Scene.highlight_terms: string[] = []`; `video.timing_mode: natural|fit_target = natural`; `ModelConfig.watermark: bool = false`, `instruction: string = ''`; `publishing.auto_publish_after_approval: bool = false`. Existing requests may omit them. Natural mode preserves measured voice speed; multi-sentence clips use proportionally estimated sentence subtitle intervals. Highlight edits invalidate render/approval while retaining unchanged source media. The renderer cache includes these inputs and an algorithm revision.

Approved automatic publications are queued transactionally for bound accounts and reserve a shared phone at claim time. Publication snapshots retain `auto_publish`; public records expose that read-only flag. `Review.auto_publish_expected` optionally binds the mode displayed by the client. `submit_started_at` permanently fences an attempted final click until success or an explicit user statement that it did not publish. Unknown results cannot resume; canceling a fenced record requires `confirmed_not_published=true` plus notes. Successful publication and its job checkpoint commit atomically. Backup restore disables automatic publication as well as generation schedules/models.

Device PINs are explicitly stored per project and serial in the local macOS Keychain, never in project files or process arguments. Background reads fail closed without authentication UI. A durable non-secret attempt latch prevents PIN retries after an uncertain or failed unlock; explicit credential lifecycle actions can reset it. Cloud voice IDs remain supported by their matching configured model; the following amendment adds a separately authorized local path.

Wireless ADB transports expose `host:port` instead of the physical device serial. Only while the keyguard is showing, the device boundary reads `ro.serialno` through that already-authorized transport and uses the validated physical value for Keychain lookup and the non-secret retry latch; all ADB commands continue targeting the connected transport. An empty, invalid or unreadable property fails back to the transport identity and therefore manual unlock, never to another credential. Xiaohongshu 9.46 recognizes the verified `编辑主页`, `从相册选择 / 拍摄与直播`, and `全部 / 视频 / 照片` surfaces. When its custom grid does not expose the fingerprint filename, selection remains a user handoff rather than a coordinate guess.

## Local voice and photo avatar amendment (2026-09-10)

`settings.local_ai` defaults to `{voice_enabled:false,avatar_enabled:false,voice_model:'qwen3',emotion_strength:0.65,reference_audio_asset_id:null,reference_text:'',portrait_asset_id:null}`. Existing settings clients may omit it. Enabling requires installed components and validated local references. No database schema migration is required; assets/settings/jobs use existing tables.

`voice_reference` accepts validated audio of 3–30 seconds, at most 30 MB. `portrait` accepts decoded images with minimum side 256 px, at most 20 MB and 40 million pixels. Derived lip-sync assets use kind `avatar`. Profile changes never mutate existing approved or published snapshots.

`GET /local-ai/status` is read only and returns `{tts,avatar,transcribe,busy,revision}`; each component includes `{installed,model,engine,reason?}`. It never downloads or executes a model. `POST /local-ai/transcribe` accepts `{asset_id}`; the queued result is `{transcript,source_asset_id,local:true}` and does not automatically save the text. `POST /local-ai/preview` accepts `{kind:'voice'|'avatar',text?:string,audio_asset_id?:string}` and returns a queued job. Voice text is limited to 500 characters; avatar preview uses the selected local audio or the reference recording. Both actions honor existing idempotency and error envelopes. Preview results contain `{asset_id,kind,duration,local:true,engine,elapsed_seconds}`.

`local_voice` requires existing scene images and a configured reference. It creates a new version, replaces scene narration using local voice generation, renders, optionally overlays the local avatar, and requires review again. This stage never calls cloud text/image/speech providers. Ordinary asset generation continues to preserve user-selected narration.

Runtime identity is pinned to Qwen3-TTS 1.7B Base via MLX, MuseTalk 1.5 via Apple MPS, and Whisper tiny on CPU. Missing installation fails closed, without cloud/model substitution. Model subprocesses cannot access the network and receive no inherited cloud credentials. Shared locking serializes local inference; contention requeues the job. Timeouts are 600 seconds for each voice clip, 1800 seconds for an avatar clip, and 300 seconds for transcription; cancellation terminates and reaps the owned process group. Frozen reference hashes, input text, portrait and model revision participate in cache identity. Validated checkpointed results can recover after restart; uncheckpointed output is not treated as success.

## Picture layout and model-directed animation amendment (2026-09-11)

Scene adds `motion: auto|none|push_in|pull_out|pan_left|pan_right = auto` and `transition: fade|cut = fade`. Old stored scenes may omit both. Legacy PATCH requests preserve existing explicit choices when these fields are omitted; adding default fields alone does not invalidate a current video. Explicit motion changes invalidate review and derived video while retaining source image/audio assets.

`POST /contents/{id}/generate` adds `stage=motion`. Preflight requires scenes with existing image/audio references and narration, a configured enabled text model, remaining call/video allowance, and local media tools. It snapshots only the title and each scene's id/caption/narration/image_prompt. It invokes the existing text provider once to return `{scenes:[{id,motion,transition}]}` using concrete motion choices (excluding auto), then renders with existing sources and optional local avatar. Unknown keys, duplicate/missing/extra IDs and unsupported values are rejected as `MODEL_OUTPUT_INVALID`. Facts, narrative, source references, and ordering are preserved. No image or speech generation occurs in this stage.

The existing version locks, idempotency key, billing intent, unknown-result guards and task recovery rules apply. A completed animation plan is checkpointed independently of rendering. The final content requires review. The frontend holds its generation lock throughout the confirmation dialog, saves dirty input before queueing, and does not submit duplicate calls on repeated clicks.

Renderer revision 6 and avatar-overlay revision 2 invalidate previous render caches. Images fit inside a separate picture region, with movement margins sufficient for every allowed animation endpoint. Scene headings and cover titles stay above it; subtitles and the presenter use the lower area. No database schema migration or additional rendering dependency is introduced.

## Chatterbox, image redraw and X amendment (2026-09-11)

`voice_model` accepts `qwen3|chatterbox`. `emotion_strength` must be finite in `[0,1]`, default `0.65`; it is passed to Chatterbox's real exaggeration control. The current user's saved value is `0.75`, independently of the product default. Chatterbox requires reference audio but no transcript; Qwen3 still requires both. `/local-ai/status` adds a `chatterbox` component. A voice `/local-ai/preview` may override either setting without changing defaults; avatar previews reject these voice-only fields. Model, strength and input hashes are frozen in jobs/cache keys. Chatterbox uses Chinese, 24 kHz reference audio, `cfg_weight=0.35`, and the existing 600-second voice timeout. Pinned S3 tokenizer, Cangjie mappings and Chinese segmenter must all load offline; failure cannot select another model implicitly.

`POST /contents/{id}/generate` adds `{stage:'images',scene_id?:string}`. `scene_id` is valid only for this stage. Preflight validates the target, existing narration, remaining source images, image provider and quotas before creating a new version. Only selected images and derived outputs are invalidated; all existing audio and non-target images are retained. Omitted `scene_id` redraws all scene images. Requests use per-version fingerprints; same-job retries reuse successfully stored provider output. Current narration, caption and the highest matching source claim constrain image prompts. New output requires review again. Old clients and existing source media remain compatible.

`x` reads the fixed public syndication timeline. `x_tikhub` uses `GET https://api.tikhub.io/api/v1/twitter/web/fetch_user_post_tweet` with `screen_name`, no cursor and one page only. `PUBLISHER_TIKHUB_API_KEY` is an optional local secret (empty by default), sent only in the Bearer header; keys are not accepted by the settings API. Calls share `limits.daily_calls` and use existing `ModelCall.kind='source'`. They use a 60-second timeout, 4 MB success-response bound, no redirects and no implicit retry. Successful raw data is checkpointed before parsing. Known HTTP/business rejections are `FAILED`; 5xx/read/partial-response uncertainty uses the existing unknown-outcome guard. Bounded HTTP error bodies produce only a static safe reason category, never arbitrary provider error text. Exact billing remains unknown without a provider bill.

Collect requests bind their source snapshot and expected kind to idempotency keys; a mismatch is `SOURCE_PROVIDER_CHANGED` or `IDEMPOTENCY_CONFLICT`. Old jobs without a paid snapshot cannot acquire a new paid source after edits. Missing key returns `TIKHUB_NOT_CONFIGURED`; quota exhaustion returns `DAILY_CALL_LIMIT`. Parsers preserve original authors/URLs and support legacy tweets, visibility wrappers, long notes, quotes and retweets. They filter to recent technology/AI posts; malformed/auth-wall responses fail rather than becoming synthetic data. No new tables, migration, server dependency or hosting service is introduced. The authorized local TTS environment adds only `spacy-pkuseg`, `srsly` and `catalogue`; existing pinned dependency versions remain unchanged.

## V2 production quality and growth amendment (2026-09-13)

The frozen implementation source is `docs/v2-production-quality-growth-spec.md`. Existing Worker, SQLite transaction, model-call idempotency, unknown-outcome, publication fence and device reservation rules remain authoritative.

- `GET /presets` returns the immutable versioned presets `tech_brief_video_v1`, `data_explainer_video_v1`, and `avatar_commentary_video_v1`. Content adds `preset_id` and `brief`; older rows default to the tech brief preset and an empty Brief.
- `POST /contents/{id}/generate` accepts `stage=brief`. It uses one guarded text call and stores exactly three schema-validated concepts; code supplies call-count estimates and leaves cost `null`. If a Brief exists, `script`, `all`, and approval require `selected_concept_id`. `POST /contents/{id}/brief/select` `{version,concept_id}` advances the version and clears script, scenes, derived media and approval state. - Scene adds `scene_type:image|text_card|stat_card|quote_card`, bounded `visual_data`, `hero_moment`, and `shot_intent`. Legacy scenes normalize to image. Card types render locally to 9:16 PNG; `stat_card` and `quote_card` must match a verified Fact source before quality can pass.

- Detailed Job responses add a sanitized `timeline` assembled from JobStep and ModelCall plus `cost:{estimated_usd:null,actual_usd:null,status:'UNKNOWN'}`. Only numeric whitelisted usage fields are exposed; provider bodies, signed URLs and missing costs are not inferred.
- Migration `0003` adds Content/Approval columns and the four V2 table groups. Downgrading removes V2 data; use the verified pre-upgrade backup for recovery.
