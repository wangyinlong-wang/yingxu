# 运营工作台界面改版

日期：2026-09-20。范围：现有 Vue 3 / Element Plus 前端，保持 FastAPI、数据库、发布状态机和八个路由契约。Kimi Code CLI 主力实现，Grok CLI 独立测试，主 Agent 制定方案与验收。

## 现状与目标

本轮通过实际运行的本地工作台检查了三个步骤：

1. 总览：真实统计与空态可用，但最近任务时间线过长，待审核/失败任务没有直接处理入口，用量信息被挤到页面底部。
2. 内容工作台：已有完整编辑和审核能力，未选内容时大面积留白，窄列表内搜索与状态选择拥挤。原状态选项显示内部英文值。
3. 发布与设备：已有自动发布提示和手机离线提示，但账号、设备与人工处理入口层级较弱，平台字段显示内部代码。

目标是让单人运营者快速知道“现在有什么要处理、到哪里处理”，并在窄屏仍能访问所有导航和表单。以浅色导航、蓝色主操作、统一边框/间距、明确文本状态替换松散的信息布局。保持现有信息与操作，不新增装饰性数据、虚假增长率或新平台支持声明。

## 本轮实现契约

- 总览统计来自现有接口；总量不写成今日数量。待审核和失败任务链接带合法状态筛选，最近内容直达现有编辑页。
- 任务列表与总览后台刷新保留已有内容，失败时展示非阻断提示，恢复后清除错误；防止请求重叠或旧响应覆盖。
- 状态筛选只接受现有枚举；保留 `content_id` 深链接与未保存编辑保护。
- 统一设计变量、按钮/表格/卡片/表单样式；移动导航采用可关闭、支持键盘的菜单，窄屏弹窗不超出可视区域。
- 发布页保留所有审核、自动发布、结果不明核验提示及确认动作；设备离线时说明调试连接步骤。
- 加载中、离线、错误、空结果分别展示；错误不被空态遮蔽，未知费用不显示为零。
- 不修改后台 API、数据库、模型凭据、设备绑定、自动发布开关或真实运营数据。

## 验收边界

使用现有前端类型检查、单元测试、构建及隔离 API 的浏览器回归测试。真实页面只做读取与导航检查；生成、审核通过、上传、最终发布均不在本轮测试操作范围。

手机连接与应用版本需以当前 ADB 真机证据为准。浏览器 390px 视口验证只能证明响应式页面表现，不能替代手机发布链路验收。
